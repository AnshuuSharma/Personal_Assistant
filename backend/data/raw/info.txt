# SECTION: Project - ResumeIQ (Overview)

ResumeIQ is Anshu's flagship AI project — a fully deployed agentic resume 
analyzer built using LangGraph. It analyzes a candidate's resume against a 
job description and provides detailed feedback including ATS score, skill gap 
analysis, job market insights, and curated learning resources. The project is 
live and accessible at https://agentic-resume-analyzer.netlify.app/ with a 
Flask backend deployed on Render and a single-page frontend on Netlify.

# SECTION: Project - ResumeIQ (Architecture and Workflow)

ResumeIQ is built as a stateful LangGraph pipeline with 4 nodes: extract, 
agent, tools, and analyze. When a user uploads their resume and a job 
description, the system first uses PyMuPDF to extract raw text from the PDF. 
The extract node then uses a llama-3.1-8b-instant model to parse this text 
into a structured JSON containing skills, experience, projects, and required 
and preferred skills from the JD. This structured data is stored in the 
LangGraph state and passed forward through the pipeline.

The agent node receives this structured data and makes an LLM call using the 
20b parameter model to decide which tools to invoke based on the identified 
skill gaps. The ATS keyword checker is hardcoded to always run, while the 
agent autonomously chooses whether to call the Adzuna job market API and the 
YouTube Data API based on what gaps it finds in the candidate's profile.

The tools node executes the decided tools and updates the state with their 
results. Finally the analyze node receives the full state — resume data, JD 
data, and all tool results — and makes a third LLM call using the 20b model 
with a structured prompt to generate a comprehensive analysis. The graph 
structure is linear: extract → agent → tools → analyze → END. Chat 
functionality is handled outside the graph, called directly from the REST API 
endpoint.

In total ResumeIQ makes 3 LLM calls per full analysis: one in the extract 
node using the 8b model, one in the agent node, and one in the analyze node 
both using the 20b model.

# SECTION: Project - ResumeIQ (ATS Keyword Checker)

The ATS keyword checker is a custom Python function Anshu built from scratch. 
It computes a keyword match percentage between the resume and job description 
using set intersection — finding matched keywords as the intersection of JD 
words and resume words, and missing keywords as the difference. The match 
percentage is calculated as the number of matched keywords divided by total JD 
keywords multiplied by 100. It also checks resume formatting by verifying 
whether standard sections like skills, education, projects, and experience 
exist in the resume, and flags any missing sections as formatting issues. The 
function returns the match percentage, top matched and missing keywords, 
formatting issues, and an overall ATS pass or fail based on whether the match 
percentage is above 60 percent and there are no formatting issues.

# SECTION: Project - ResumeIQ (Tool Orchestration)

ResumeIQ orchestrates 3 tools. The ATS keyword checker always runs as 
described above. The Adzuna job market API is called when the agent identifies 
skill gaps — it returns the number of active job listings for a skill and 
average salary data, giving the candidate a real sense of how in-demand their 
missing skills are in the current market. The YouTube Data API is called to 
find relevant learning resources for the missing skills, so the candidate gets 
actionable course recommendations directly in the analysis. The agent node 
uses an LLM call to autonomously decide which of the latter two tools to 
invoke based on the candidate's specific skill gaps.

# SECTION: Project - ResumeIQ (Token Management and Chat)

One of the hardest engineering challenges Anshu solved in ResumeIQ was 
managing token usage wisely across the pipeline given the constraints of free 
tier LLM APIs. With a resume, job description, and tool results all being fed 
into prompts simultaneously, token usage can spike quickly. Anshu addressed 
this by using a smaller 8b model for the extraction node where structured 
output matters more than reasoning depth, and reserving the 20b model only 
for the agent and analysis nodes where quality is critical. This dual model 
architecture effectively doubled the token budget while maintaining output 
quality.

For chat memory Anshu implemented a custom history compression function that 
keeps the first 2 messages for context and the last 10 messages for 
continuity, discarding the middle of long conversations. This keeps the chat 
context window lean without losing important context. Instead of sending the 
full resume to every chat turn, only the extracted skills, experience, 
projects, and missing skills are sent — significantly reducing per-turn token 
consumption. Anshu is actively continuing to improve token efficiency in the 
project.

# SECTION: Project - Personal Assistant (Architecture)

The personal assistant is built on a RAG (Retrieval Augmented Generation) 
pipeline. When a recruiter asks a question, the query is converted into a 
vector embedding using the all-MiniLM-L6-v2 sentence transformer model. 
ChromaDB is used as the local vector database storing 16 chunks of 
structured information about Anshu. Semantic search retrieves the most 
relevant chunks which are passed as context to Gemini 2.0 Flash for 
response generation. The system maintains short term session-based chat 
memory by keeping the last 6 conversation turns, allowing natural 
follow-up questions without repeating context.
